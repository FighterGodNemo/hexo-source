把 Strata、PolyStrata、TensorFold 这三个名字放在一起，第一反应是"三个竞品，选一个"。真正拆开看会发现完全不是：它们都在解决同一个问题——**在有限的消费级硬件上跑大模型**——但各自选择了牺牲不同的维度。

Strata 牺牲速度换容量（125B 也能跑），PolyStrata 牺牲深度换广度（12 个模型一个端点），TensorFold 路线牺牲容量换速度（显存塞得下的模型跑到极致）。所以本文的"对比"实际是一次**取舍坐标系的比较**：同样受显存限制，三条路线各自的极限在哪、崩点在哪、适用边界在哪。

---

## 一、三条路线的研究对象

| 名称 | 本报告所指 | 一句话定位 |
|---|---|---|
| **Strata** | `Niko1221/Strata`（MIT，C/C++） | 单模型、深度优化的本地 MoE **分层推理引擎** |
| **PolyStrata** | `VecSzn/PolyStrata`（基于 Strata，MIT） | 多模型、双引擎的**服务层**：一个端点管 12 个模型 |
| **TensorFold 路线** | MLX 生态的 affine 低比特推理引擎（含社区 1.x 版本线） | **全驻留 + 低比特**，只追单请求极速的引擎 |

一句话区分三者的技术信仰：

- **Strata**：显存不够没关系，把冷数据摊到内存和 SSD，用调度把时间换回来；
- **PolyStrata**：单个模型喂不饱所有场景，那就把"多模型"当成一等公民来做；
- **TensorFold**：分层本身有代价，不如把模型压到能全塞进显存，之后彻底不做调度。

这三种信仰互相排斥，所以三条路线的性能特征、失败模式、适用硬件都不一样。

---

## 二、一句话结论

> **同一个"本地跑大模型"的问题，三条路线给出三个方向相反的答案：Strata 用分层换容量，PolyStrata 用广度换覆盖，TensorFold 用全驻留换速度。要比较的不是"谁更强"，而是"你愿意牺牲哪一维"。**

- **Strata**：能跑 125B 级 MoE，代价是输出速度落到个位到几十 token/s——**牺牲速度换容量**；
- **PolyStrata**：一个端点装 12 个模型、双协议兼容，代价是单模型不做到极致——**牺牲深度换广度**；
- **TensorFold 路线**：显存放得下的模型能跑到极高吞吐，代价是模型档位被显存死锁——**牺牲容量换速度**。

三种取舍互不重叠，所以它们不是竞品，而是同一张选择题上的三个选项。

## 三、Strata：把"放不下"变成"不需要同时放下"

### 3.1 问题定义

Qwen3.8-Flash-Next 是 125B 总参数、约 6B 激活参数、**24,576 个专家**的 MoE 模型。4bit 量化后权重仍有 60GB 量级，而主流消费级显卡显存停在 12–24GB。"全量驻留显存"的传统推理方式下，这堵墙绕不过去。

Strata 的核心动作只有一个：**把"必须大显存"的需求，降级成"必须大内存"**——容量交给内存条，速度交给显存。

### 3.2 三级存储分层

| 层级 | 放什么 | 为什么放这里 |
|---|---|---|
| **显存（VRAM）** | attention 与 DeltaNet mixer、gated-residual 权重、router、shared experts、output head、MTP 草稿层、KV cache，以及剩余显存全部灌入的**专家缓存** | 每 token 都要用、延迟敏感的热路径 |
| **内存（RAM）** | **全部 24,576 个专家，全部 pinned** | MoE 稀疏性：每 token 只要约 10 个专家，但"哪 10 个"随时变，所以必须全部可寻址 |
| **SSD** | 28.8GB 的 **n-gram 查表**（PLE 表），每 token 只读几行，`O_DIRECT` 绕过页缓存直读 | 体量大但访问极稀疏，容许高延迟 |

这里藏着一个决定成败的判断：**Strata 没有把"专家权重"放到 SSD，它把"查表"放到了 SSD。** 同样是"用 SSD 扩容量"，两件事的性质完全不同——查表允许毫秒级延迟，专家权重不允许。

### 3.3 CPU 不是配角：真并行而非降级回退

业界对"CPU 参与推理"的固有印象是降级：GPU 忙不过来才甩给 CPU，两边抢同一份数据。Strata 的做法相反：

- **专家全员 pinned 在内存里**，CPU 直接**原地计算**未上卡的那部分专家（AVX-512 / AVX2 kernel），不需要先拷到别处；
- CPU 与 GPU **同时工作**：GPU 算缓存中的专家，CPU 算没命中的，二者谁都不等谁；
- 最终只把计算结果搬回显存参与合并。

配合两条投机解码：**MTP 层起草最多 3 个 token、一次前向验证 48 层**；**prompt lookup 起草最多 5 个 token**（在代码编辑类负载下带来 6–11% 的额外提速）。

### 3.4 三个不那么显眼但很实用的机制

1. **显存容量经济学**：每多 1GB 显存约多放 **700 个专家**——这条经验值可直接用来做硬件规划。
2. **专家缓存自适应**：高频专家常驻显存、冷门回内存，且会随对话主题**在线学习**（聊代码时命中的专家集和聊历史时不同）。
3. **chunked prefill**：分块 8,192 token（可配到 32K），专家经 PCIe **流式上卡**，结果常驻显存、不重复搬运；ring buffer 按字节而非按块计量。

### 3.5 覆盖面（成熟度远超"玩具"）

NVIDIA RTX 20–50 系、AMD RX 7000/9000（RX 6000 实验性）、Intel Arc（Linux）、Apple Silicon、Strix Halo、DGX Spark 全在支持列表；桌面 App、终端 `strata launch`、Docker、源码构建四条安装路径齐备。除 Qwen3.8-Flash-Next 外，也支持 DeepSeek V4.1-Flash-1017 这类 **191–274GB** 的巨无霸——那种规模就必须走"权重溢出到 SSD"的路径了，代价是输出掉到个位数 token/s。

## 四、PolyStrata：从"一个引擎"到"一个引擎矩阵"

### 4.1 架构上的真实变化

PolyStrata 常被误当成"Strata 的另一个下载地址"。它的 README 说得很清楚：**12 个模型，两套引擎**。

| 引擎 | 负责的模型 | 来源 | 特点 |
|---|---|---|---|
| **Strata 原引擎**（未改动） | Qwen3.8-Flash-Next | 直接来自 `Niko1221/Strata` | 24,576 专家、三级分层、AVX-512 CPU 并行那套完整机制 |
| **PolyStrata 自研引擎**（`strata-poly`） | 其余 11 个模型 | VecSzn 自写，复用 llama.cpp/ggml 部分代码 | 需要单张 NVIDIA 卡、可双卡；GLM 5.3 Flash 与 DeepSeek V4 Flash 仅 Linux |

这是典型的**分叉经济学**，而且是清醒的那种：把最难的（125B / 24,576 专家）继续交给上游原引擎，不碰、不改、随上游升级；把"模型覆盖面"这件上游不打算做的事自己做。代价是维护两条代码路径，收益是广度。

### 4.2 覆盖面矩阵（这才是它的架构主张）

| 模型 | 文件体积 | 8GB 笔记本（写/读） | RTX 5090（写/读） |
|---|---|---:|---:|
| LFM2.5-24B-A2B | 11–25 GB | 70–73 / 3,590–3,620 | 480–485 / 23,390–23,460 |
| Flint 40B-A2.5B | 18–42 GB | 61–63 / 2,000–2,010 | 251–252 / 12,900 |
| Qwen3.6-35B-A3B | 13–23 GB | 94–100 / 1,690 | 394–395 / 7,800–7,810 |
| Gemma 4 26B-A4B | 11–17 GB | 92–93 / 2,240 | 353–356 / 8,420–8,480 |
| Tiel Coder 35B-A3B | 14–23 GB | 83 / 1,700 | 337–345 / 8,080–8,110 |
| MiniCPM-V 4.7 35B-A3B | 16–29 GB | 64 / 1,150 | 308–311 / 7,910–7,950 |
| Kolibri 1 | 29–48 GB | 未测 | 189–192 / 4,980–5,070 |
| GLM 5.3 Flash | 79–114 GB | 跑不了（需 32GB 显存） | 59–66 / 820 |
| DeepSeek V4 Flash | 91 GB | 跑不了 | 未测 |

表里有两件事值得记住：**8GB 笔记本能跑 35B MoE**（94–100 token/s）；而 **GLM 5.3 Flash 在 8GB 上不是"慢"，是"跑不了"**——它的门槛是阶跃的，不是靠调参能绕过的。

### 4.3 服务层才是它的真身份

- **一个端点**：`http://127.0.0.1:8080/v1`，**同时**兼容 OpenAI 与 Anthropic 两套协议——Claude Code、Cursor、ChatGPT 类客户端都能直连；
- **生命周期显式化**：`/v1/load`、`/v1/unload`，`switch_on_request` 允许"请求里点名另一个模型就自动切换"（等当前请求结束后执行，最多 120 秒，超时返回 409）；
- **契约写进 HTTP 状态码**：有请求在跑或排队返回 **409**，未知模型返回 **404**——这种"把资源竞争状态显式暴露"的设计，比静默排队诚实得多；
- **内置 UI**：Chat、实时 **Monitor**（GPU/CPU/内存）、About，模型热切换不用碰命令行。

### 4.4 工程细节：为"弱硬件"做的适配

- **chunked GDN prefill**：把长提示的 prefill 切块，避免一次性吃满显存；
- **streaming CPU copies for expert staging**：专家上卡走流式拷贝，不与计算争带宽；
- **size-class MMQ launches**：按专家尺寸分档发射 kernel，减少小批次浪费；
- **RTX 20（Turing, sm_75）专属 kernel 系列** + 一批 CUDA opt-in 开关，默认全关，按需打开。

这些细节说明一件事：PolyStrata 的"广度"不是堆模型列表堆出来的，而是靠一层层硬件适配换来的。

## 五、第三条路线：全驻留 + 低比特量化

### 5.1 它和前两条路线的位置关系

前两条路线都在"显存不够"这个前提下做文章：Strata 把冷数据搬出显存，PolyStrata 把多个模型轮流搬进显存。第三条路线反其道而行——**承认显存就是天花板，然后想办法把天花板压到模型能装下**。

它的核心逻辑只有一句：**只要模型能被压到显存装得下，就完全不需要调度。**

这条路线属于 MLX 生态的量化与运行时（TensorFold 及其衍生版本），和 llama.cpp / ggml 是同一层级的两种实现选择，不是上下游关系。

### 5.2 三个技术手段

| 手段 | 做法 | 解决了什么 |
|---|---|---|
| **affine 分组量化** | 权重按 group（常见 64）分组做仿射量化，典型 4bit | 把 27B 级模型的权重压到 20GB 内，单卡可容纳 |
| **低比特 KV 缓存** | KV cache 用 FP8 等格式存，而非 FP16 | 长上下文时显存占用大幅下降，支持 256K 级上下文 |
| **草稿模型投机解码** | 用一个小草稿模型先起草多个 token，主模型一次前向批量验证 | 把 decode 阶段从"逐 token"变成"批验证"，吞吐成倍提升 |

这三个手段是配套的：量化压低权重占用 → 省下的显存用来放更长上下文 → 投机解码把每次前向的收益放大。三者叠加才形成这条路线"吞吐极高"的特征。

### 5.3 与 llama.cpp / GGUF 路线的架构差异

两条路线跑同一个模型、同一张卡，性能可以差很多倍。差异不在"谁更聪明"，而在四个可解释的架构选择：

1. **量化族的自由度不同**：GGUF 的 K-quant 是"整块/整行"的非线性量化，位宽档位较粗；MLX 的 affine 分组量化以 group 为单位，粒度更细，同等位宽下的精度分布不同。
2. **KV 缓存格式不同**：GGUF 路线常用 q8_0 / q4_0 存 KV，MLX 路线可走 FP8——影响的是长上下文下的显存占用与带宽。
3. **kernel 实现不同**：ggml 的 kernel 面向"跨平台一致性"设计，MLX 的 kernel 更贴近特定后端（Metal / CUDA）做特化。
4. **调度哲学不同**：llama.cpp 追求"一个二进制跑遍所有平台"，MLX 路线追求"在目标硬件上榨到极限"。

**这就是为什么同模型同卡会出现数倍差距——它不是玄学，是量化粒度、KV 格式、kernel 特化、调度哲学四个变量叠加的结果。** 反过来说，任何"哪个引擎更快"的结论都必须绑定具体模型、位宽、上下文长度与硬件，脱离这些条件的对比没有意义。

### 5.4 代价与硬约束

| 约束 | 具体表现 | 影响 |
|---|---|---|
| **显存墙** | 模型压不进显存就直接跑不了，没有"降速运行"的中间态 | 容量天花板由卡决定，不做妥协 |
| **量化质量损失** | 4bit affine 对长尾知识、精确计算类任务有可感损失 | 适合对话/生成，不适合高精度场景 |
| **并发能力弱** | 单卡单模型，多请求只能排队 | 不适合多人共用 |
| **迭代速度快** | 引擎版本频繁更新，同权重不同版本性能差异明显 | "当前最优"结论有保质期 |

**最关键的差异在这里**：Strata 的显存不足是**连续的**（显存少一点，慢一点），TensorFold 路线的显存不足是**阶跃的**（装不下就别跑）。这个性质决定了选型逻辑——前者可以"凑合"，后者不能。

| 维度 | **Strata** | **PolyStrata** | **TensorFold 路线** |
|---|---|---|---|
| **路线** | 分层卸载 | 多模型聚合 | **全驻留 + 低比特** |
| **核心解决** | 权重放不下 | 模型类型/版本太多 | 单请求吞吐不够 |
| **抽象单位** | 专家（expert） | 模型（model） | 层与 KV（kernel 级） |
| **权重驻留** | VRAM + RAM（全专家 pinned）+ SSD（仅查表） | 两套引擎各自策略，模型可热切换 | **100% VRAM，无分层** |
| **调度粒度** | 每 token 的专家级调度 + CPU/GPU 并行 | 请求级 + 模型级（load/unload） | **几乎无调度** |
| **关键机制** | 自适应专家缓存、MTP 投机解码、chunked prefill、PLE 直读 | 双引擎并存、双协议兼容、模型热切换、成组 kernel 适配 | affine 分组量化、FP8 KV、草稿投机解码 |
| **容量弹性** | **连续**（显存少则变慢） | 中（模型可换，单个模型仍受显存限） | **阶跃**（装不下即不可用） |
| **扩展方向** | **深**：单模型榨到极致 | **广**：模型覆盖面最大化 | **快**：单请求延迟最小化 |
| **主要失败模式** | PCIe/内存带宽、缓存命中率、量化损失 | 上游分叉维护、后端适配矩阵 | 显存墙、量化精度、并发能力 |

## 七、四个关键切面的深入对比

### 7.1 容量经济学：三种不同的"货币"

- **Strata 用显存换专家**：官方给过一条罕见的经验值——**每 1GB 显存约多缓存 700 个专家**。24,576 个专家的模型里，12GB→16GB 的升级约等于多缓存 11% 的专家池。这是一条可以直接用于硬件规划的曲线。
- **PolyStrata 用显存换模型覆盖**：它的容量单位是"整个模型"。8GB 显存能跑 13–23GB 的 35B-A3B，靠的是层与专家混合调度；但 79–114GB 的 GLM 5.3 Flash 在 8GB 上毫无办法——**它的门槛在某些模型上是硬的**。
- **TensorFold 路线用显存换位宽与上下文**：省下的显存不给"更多模型"，而是给"更低比特 + 更长上下文"。

三种货币不能互换，这解释了为什么三条路线不存在"谁替代谁"。

### 7.2 调度粒度：token 级 / 请求级 / 无调度

- **Strata：token 级**。每生成一个 token 都要决策"哪些专家在显存、哪些走 CPU、哪些经 PCIe 换入"。决策频率最高，优化空间最大，但每次决策都可能出错（缓存不命中）。
- **PolyStrata：请求级 + 模型级**。它调度的是"哪个模型服务这个请求""什么时候 load/unload"，并把资源竞争状态写进 HTTP 契约（有请求在跑返回 409、未知模型返回 404）——**把并发冲突显式暴露，比静默排队诚实**。
- **TensorFold 路线：几乎无调度**。权重全在显存，每次前向只是纯计算；复杂度被推到编译期和量化期，运行期极简。

一个反直觉的观察：**调度粒度越细，运行期优化空间越大，但工程风险也越高**。三条路线的成熟度与它们的调度复杂度大致呈反比——这不是巧合，而是"运行期智能"必然要用可靠性来换。

### 7.3 I/O 语义：三种完全不同的数据路径

| 路线 | 热路径上的数据流 |
|---|---|
| Strata | VRAM ↔ RAM 经 PCIe 换专家；SSD 只走**查表**（n-gram 表 `O_DIRECT` 直读，绕过页缓存） |
| PolyStrata | VRAM ↔ RAM 换层与专家，模型切换时整模型重新加载 |
| TensorFold 路线 | **无热路径 I/O**：加载完成后权重不动，只有计算 |

Strata 在 I/O 上有个值得记一笔的细节：它的 PLE 表默认走 `O_DIRECT` 直读，因为这张表每 token 只读几行，走页缓存纯属污染缓存；同时它**只告警不自动切换**（SATA SSD 的直读速度只有 NVMe 的零头，同一阈值会误判）——**用探针提示而不是替用户做决定，这个工程取舍很克制**。

### 7.4 抽象断点：为什么三条路线都挂在一个 `/v1` 上

Strata 的桌面 App、PolyStrata 的服务、TensorFold 路线的运行时，对外暴露的都是 **OpenAI 兼容 API**（PolyStrata 还额外兼容 Anthropic 协议）。

这意味着上层应用——Claude Code、Cursor、各类 Agent 框架——**完全不需要知道底层用的是哪条路线**。它只看到一个 `/v1/chat/completions`。

这才是本地推理生态真正的分水岭：**引擎之间打生打死，但接口统一在 `/v1` 上，所以上层应用可以毫无代价地换引擎**。谁的实现更好，用户换一行 base URL 就能验证。

## 八、性能与代价：公开数据能说明什么

三条路线的公开数据（各项目 README 自测，注意**不可直接横向比较**——模型不同、硬件不同）：

| 路线 | 典型配置 | 输出速度 | 说明 |
|---|---|---|---|
| Strata | Qwen3.8-Flash-Next（IQ2_XS），12GB 显存 + 64GB 内存 | 79 token/s（32K 提示读取 2,090 token/s） | 唯一能用这点显存跑 125B 的路线 |
| Strata（巨模型） | DeepSeek V4.1-Flash 级模型，显存不足需溢到 SSD | 个位数 token/s | 溢出到 SSD 的代价 |
| PolyStrata | Qwen3.6-35B-A3B，8GB 显存笔记本 | 94–100 token/s | 弱硬件也能跑 |
| PolyStrata | 同一模型，RTX 5090 32GB | 394–395 token/s | 桌面卡上限 |
| PolyStrata | GLM 5.3 Flash（80GB+ 级） | 59–66 token/s（需 32GB 显存） | 8GB 卡上**跑不了**，不是慢 |
| TensorFold 路线 | 27B 级模型 4bit，单张高端卡全驻留 | 数百 token/s 量级 | 全驻留的红利，但模型档位受限 |

**从这张表能读出三个非直觉结论：**

1. **"能不能跑"和"跑多快"是两个不同的问题**。Strata 在 12GB 上跑 125B 靠的是"慢一点也要跑起来"；PolyStrata 的 GLM 在 8GB 上是"根本跑不了"。前者是连续降级，后者是阶跃拒绝——**选型时先判断自己面对的是哪一种约束**。
2. **显存的价值不在容量，而在"让多少数据不必落到慢介质上"**。同一路线下从 12GB 换到 32GB，收益不是线性的，而是取决于命中率曲线的陡峭段在哪。
3. **同模型跨引擎的差距可以远大于同引擎跨硬件的差距**。这意味着"加钱换卡"和"换个引擎"是同一预算下的两个竞争选项，而后者往往被忽略。

## 九、风险与坑：三条路线各自的失败模式

### Strata 的失败模式

| 风险 | 实情 | 应对 |
|---|---|---|
| **SSD 寿命** | 常被高估。主线设计里 SSD 只承担查表，读放大远大于写放大 | 不必当主要顾虑，但也别在低速 SATA 盘上跑 |
| **PCIe / 内存带宽** | 才是真正的热路径瓶颈：专家换入换出全靠总线 | 双通道高频内存、直连 PCIe 通道 |
| **缓存命中率** | 话题越分散，命中率越低，速度掉得越快 | 固定用途（如只写代码）收益最大 |
| **量化质量** | 2bit 级的激进量化的确伤精度 | 精度敏感场景别省那点显存 |

### PolyStrata 的失败模式

| 风险 | 实情 | 应对 |
|---|---|---|
| **上游分叉维护** | 双引擎意味着两条代码路径，上游更新要跟两次 | 关注它的上游同步节奏 |
| **后端适配矩阵** | 模型 × 显卡 × 操作系统 的组合爆炸，总有些组合是实验性的 | 用官方标注"已验证"的组合 |
| **大模型硬门槛** | 80GB 级模型在 8GB 卡上不是慢，是不可用 | 先确认目标模型的实际门槛 |

### TensorFold 路线的失败模式

| 风险 | 实情 | 应对 |
|---|---|---|
| **显存墙是阶跃的** | 模型压不进显存就直接不可用，没有降速选项 | 按最坏情况（最长上下文）算显存 |
| **量化精度** | 4bit affine 对长尾知识与精确推理有可感损失 | 高精度任务上更高位宽或换路线 |
| **版本敏感** | 引擎迭代快，同权重不同版本性能差异明显 | 锁定版本，别在生产环境追新 |
| **并发弱** | 单卡单模型，多请求只能排队 | 多人场景应选服务层方案 |

## 十、取证与安全视角

本地推理在取证与安全场景里有独特价值，也有独特的坑：

1. **数据不出机**——这是本地化最硬的价值。模型权重、提示词、对话记录全在本地，没有第三方日志。但反过来，**本机日志就是唯一证据来源**，必须确保保留。
2. **模型来源可验证**——权重文件应当能追溯（哈希或版本锁定）。一把"来历不明的 GGUF"在取证语境里是不可信的：量化过程本身可能被篡改。
3. **推理结果不完全可复现**——同一模型在不同引擎、不同量化、不同硬件上输出可能有细微差异。**取证报告里必须写清硬件、引擎版本、量化位宽与 KV 格式**，否则对方一句"换台机器就不一样"就能质疑。
4. **本地服务默认无鉴权**——几乎所有本地推理服务默认监听回环地址、不带鉴权。一旦为了"让同事也能用"改成对外监听，就是一个任何人都能读你对话历史的服务。这在实验室和内网都是常见事故。
5. **智能体层的越权风险**——如果上层接了编程智能体，它能读文件、跑命令。在取证机上部署智能体，必须假设它可能动到检材：**检材只读挂载，工作副本另放，工具调用单独落日志**。

## 十一、选型建议（按场景）

| 你的场景 | 选哪条路线 | 理由 |
|---|---|---|
| 显存 12–16GB，想跑 100B+ 级 MoE | Strata | 唯一能在这一档显存上跑起来的方案 |
| 显存 32GB 以上，只要单模型极速 | TensorFold 路线 | 全驻留无调度开销 |
| 需要同时提供多个模型/多个协议 | PolyStrata | 一个端点、双协议、热切换 |
| 8GB 笔记本想跑 30B 级 | PolyStrata | 硬件适配做得最细 |
| 需要长上下文（200K+） | 看 KV 量化与缓存策略，首选全驻留路线 | 长上下文的瓶颈在 KV，不在权重 |
| 精度敏感（审计、取证、法律） | 更高位宽 + 可复现环境 | 别为了速度牺牲可复现性 |
| 多人共用 | PolyStrata 或云端 | 单卡单模型路线做不到 |

## 结语

把三条路线摆在同一张表上之后，最值得记住的不是"哪个最好"，而是它们各自证明了什么：

**Strata 证明了容量问题可以用分层 + 并行缓解，但前提是——你必须清楚哪部分数据能容忍慢介质。把查表放 SSD 是妙笔，把专家权重放 SSD 是灾难。**

**PolyStrata 证明了"广度"本身就是一种架构能力，而"礼貌分叉"（难的部分不动上游）是 fork 生态能长期活下去的关键。**

**TensorFold 路线证明了延迟是可以被买回来的——只要你放弃容量。而且它提醒了一件事：引擎选择对性能的影响，常常比同价位换硬件更大。**

三条合起来是一句话：**没有最优架构，只有你选择牺牲哪一维，以及这个牺牲是否被清楚地写进文档。**
